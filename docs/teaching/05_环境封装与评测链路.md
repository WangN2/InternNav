## 讲解

### 5.1 为什么需要三种环境？

InternNav 支持三类平台：

| 平台 | 仿真/真实 | 物理真实性 | 速度 | 用途 |
|------|----------|-----------|------|------|
| **Habitat** | 仿真 | 低（离散动作） | 快 | VLN-CE 经典基准、快速验证 |
| **InternUtopia / Isaac Sim** | 仿真 | 高（连续物理） | 慢 | VLN-PE、真实部署前验证 |
| **RealWorld** | 真实 | 真实 | 受硬件限制 | 真实机器人 demo |

从 Habitat 到 InternUtopia 到 RealWorld，是一个从"快速验证"到"真实部署"的递进过程。

### 5.2 环境基类与注册机制

文件：`internnav/env/base.py`

```python
class Env:
    envs = {}

    @classmethod
    def register(cls, env_type: str):
        def decorator(env_class):
            cls.envs[env_type] = env_class
            return env_class
        return decorator

    @classmethod
    def init(cls, env_config, task_config):
        return cls.envs[env_config.env_type](env_config, task_config)
```

和 Agent / Evaluator 一样，环境也用装饰器注册。`@base.Env.register('habitat')` 会把 `HabitatEnv` 登记到 `Env.envs['habitat']` 里，`Env.init()` 根据 `env_type` 字符串找到对应类并实例化。

### 5.3 HabitatEnv

文件：`internnav/env/habitat_env.py:10`

```python
@base.Env.register('habitat')
class HabitatEnv(base.Env):
    def __init__(self, env_config, task_config):
        self.config = env_config.env_settings['habitat_config']
        self._env = Env(self.config)
        self.episodes = self.generate_episodes()
```

特点：

- 直接包装 Habitat 原生的 `habitat.Env`。
- 动作空间是离散整数：`0=stop, 1=forward, 2=turn_left, 3=turn_right, 4=look_up, 5=look_down`。
- 支持断点续跑：通过 `output_path/progress.json` 跳过已完成的 episode。
- 支持分布式 shard：`rank :: world_size` 切分数据。

适用：经典 VLN-CE 任务（R2R、RxR、REVERIE 等）。

### 5.4 InternutopiaEnv

文件：`internnav/env/internutopia_env.py:13`

```python
@base.Env.register('internutopia')
class InternutopiaEnv(base.Env):
    def __init__(self, env_config, task_config):
        ...
        self.env = Env(config)
```

特点：

- 基于 **Isaac Sim / InternUtopia** 物理仿真。
- 动作空间是**控制器 dict**，例如：

```python
{'h1': {'stand_still': []}}
{'h1': {'move_by_flash': [3]}}
{'h1': {'move_by_discrete': [3]}}
{'h1': {'move_by_speed': [v, w]}}
```

- 初始化流程：加载 episode → 生成 task configs → 构造 SimConfig → 注册扩展 → 创建向量环境。
- 支持 Ray 分布式向量环境。

适用：VLN-PE、Dual-System VLN、需要物理真实性的评测。

### 5.5 RealWorldEnv

文件：`internnav/env/realworld_agilex_env.py:10`

```python
@Env.register('realworld')
class RealWorldEnv(Env):
    def __init__(self, fps=30, ...):
        self.node = DiscreteRobotController()
        self.cam = AlignedRealSense()
        self.thread = threading.Thread(target=self._capture_loop, daemon=True)
        self.thread.start()
```

特点：

- 控制真实 Agilex 机器人。
- 内部开 30Hz 线程持续采集 RealSense 数据。
- `step(action)` 接收整数：`0=stand, 1=forward, 2=left, 3=right`。
- 本身**没有推理**，只是执行 Agent 输出的动作。

适用：真实世界 demo（当前部署更多用 `http_internvla_client.py` + `http_internvla_server.py`）。

### 5.6 三种环境对比表

| | HabitatEnv | InternutopiaEnv | RealWorldEnv |
|--|------------|-----------------|--------------|
| 注册 key | `habitat` | `internutopia` | `realworld` |
| 底层平台 | Meta Habitat | Isaac Sim / InternUtopia | ROS1 + RealSense |
| 动作类型 | 离散整数 | 控制器 dict | 离散整数 |
| 物理仿真 | 否 | 是 | 真实物理 |
| 主要用途 | VLN-CE 基准 | VLN-PE / Dual-System | 真实部署 demo |
| 是否支持分布式 | 是 | 是（Ray/多进程） | 否 |

### 5.7 InternUtopia 是什么？

> **InternUtopia = 基于 NVIDIA Isaac Sim 的具身智能仿真器，专门模拟机器人在真实三维场景里的物理运动和交互。**

它原来叫 **GRUtopia**，后来改名。相比 Habitat：

- 有重力、碰撞、摩擦、惯性
- 支持连续速度/力矩控制
- 加载真实机器人 USD 模型（如 H1）
- 支持 RGB-D、点云等传感器

#### 已注册的评测器

| 评测器 | key | 环境 | 用途 |
|--------|-----|------|------|
| `VLNDistributedEvaluator` | `vln_distributed` | InternUtopia | VLN-PE 分布式/单机评测 |
| `HabitatVLNEvaluator` | `habitat_vln` | Habitat | InternVLA-N1 Habitat 评测 |
| `HabitatDefaultEvaluator` | `habitat_evaluator` | Habitat | 通用 Habitat 评测 |
| `HabitatDialogEvaluator` | `habitat_dialog` | Habitat | 多轮对话 VLLN |

### 5.9 `use_agent_server` 的两种模式

文件：`internnav/evaluator/distributed_base.py:55`

```python
if eval_cfg.eval_settings.get('use_agent_server', False):
    from internnav.utils import AgentClient
    self.agent = AgentClient(eval_cfg.agent)
else:
    from internnav.agent import Agent
    self.agent = Agent.init(eval_cfg.agent)
```

| | `False`（默认） | `True` |
|--|----------------|--------|
| Agent 位置 | 评测进程内部 | 独立 HTTP Server |
| 是否支持分布式 | **支持** torch.distributed | **不支持** |
| 通信方式 | 直接函数调用 | HTTP + pickle/base64 |
| 适用场景 | 单机/多卡 | 模型独立部署 |
| 安全注意 | 无 | pickle 序列化，不要暴露公网 |

### 5.10 `vln_default_config.py` 的作用

文件：`internnav/configs/evaluator/vln_default_config.py:180`

`eval.py` 加载用户配置后，如果是 `vln_distributed`，会调用 `get_config()` 自动填充：

- H1 机器人的 USD、传感器、控制器
- 场景缩放参数（mp3d / grscene / kujiale）
- 四种模型（cma/rdp/seq2seq/internvla_n1）的默认参数
- 分布式 Ray 配置

目前只支持 **`robot_name='h1'`**，换机器人需要扩展 `get_config()` 中的分支。

### 5.11 Ray 模式是什么？

> **Ray 是一个分布式计算框架。在 InternNav 里，Ray 模式用于把多个 InternUtopia 仿真环境分布到多台机器/多个进程上并行跑。**

启用方式：

```python
task_settings={
    'use_distributed': True,
    'proc_num': 4,
}
```

启动脚本：

```bash
./scripts/eval/bash/eval_vln_distributed.sh internutopia_vec_env --config xxx.py
```

架构：

```text
Machine 0 (Head)
├─ Ray Head（调度中心）
└─ Evaluator

Machine 1/2/... (Worker)
└─ Ray Worker

Ray Head 把 env 任务分发给 Worker
```

Ray 模式与普通 `internutopia` 模式区别：

| | 普通 `internutopia` | Ray `internutopia_vec_env` |
|--|---------------------|---------------------------|
| 分布式方式 | torch.distributed | Ray |
| 分布对象 | 多个评测进程 | 多个环境 worker |
| 典型场景 | 单机多卡 | 多机集群 |
| 启动方式 | `torchrun eval.py` | `ray start --head` + worker |

### 5.13 `InternutopiaEnv` 初始化详细流程

文件：`internnav/env/internutopia_env.py:13`

```python
@base.Env.register('internutopia')
class InternutopiaEnv(base.Env):
    def __init__(self, env_config, task_config):
        # 1. 加载 episode（支持断点续跑）
        self.episode_loader = ResumablePathKeyEpisodeloader(...)
        self.episodes = generate_vln_episode(self.episode_loader, task_config)

        # 2. 把 episode 写进 task_settings
        task_settings.update({'episodes': self.episodes})

        # 3. 给 Isaac Sim 指定 GPU
        os.environ["CUDA_VISIBLE_DEVICES"] = str(env_settings.get('local_rank', 0))

        # 4. 构造 InternUtopia Config
        config = Config(
            simulator=SimConfig(**env_settings),
            env_num=task_settings['env_num'],
            env_offset_size=task_settings['offset_size'],
            task_configs=task_settings['episodes'],
        )

        # 5. 如果启用 Ray 分布式
        if 'distribution_config' in env_settings:
            distribution_config = RayDistributionCfg(**env_settings['distribution_config'])
            config = config.distribute(distribution_config)

        # 6. 注册自定义扩展（传感器、控制器、任务）
        import_extensions()

        # 7. 创建向量环境
        self.env = Env(config)
```

### 5.14 `VLNDistributedEvaluator` 状态机

文件：`internnav/evaluator/vln_distributed_evaluator.py:27`

五种状态：

```python
class runner_status_code(Enum):
    NORMAL = 0      # 正常推理
    WARM_UP = 1     # 刚 reset，正在 stand_still 稳定
    NOT_RESET = 3   # 已终止，等待 reset
    TERMINATED = 2  # 所有 episode 跑完
    STOP = 4        # 当前步是 stop 动作
```

主循环：

```python
def eval(self):
    obs, reset_info = self.env.reset()
    obs = self.warm_up()
    self.runner_status = np.full(..., runner_status_code.NORMAL)

    while self.env.is_running():
        obs, action = self.get_action(obs, action)      # Agent 推理
        obs, terminated = self.env_step(action)          # 环境步进
        env_terminate, reset_info = self.terminate_ops(...)  # 处理终止/reset
        if env_terminate:
            break
```

- `warm_up()`：stand still 直到动作完成、姿态稳定。
- `get_action()`：调用 Agent，并把输出转成控制器 dict。
- `_transform_action_batch()`：`action=[0]` → `{'h1': {'stop': []}}`。
- `env_step()`：循环调用直到 `finish_action=True`。
- `terminate_ops()`：处理 warm up 结束、episode 终止、环境 reset。

### 5.16 `vln_default_config.py` 填充逻辑

文件：`internnav/configs/evaluator/vln_default_config.py:180`

`get_config()` 自动完成：

1. 选择机器人配置（目前只支持 h1）。
2. 构造机器人：USD、传感器、控制器。
3. 如果开 flash 模式，加上 flash 控制器。
4. 场景缩放（mp3d=1，grscene/kujiale=0.01）。
5. 模型默认参数（cma/rdp/seq2seq/internvla_n1）。
6. 合并用户配置并返回。

## 小结

- 三种环境对应三种平台：Habitat（离散快）、InternUtopia（连续物理）、RealWorld（真实）。
- 环境统一通过 `Env.register()` 和 `Env.init()` 创建。
- 四种评测器对应不同场景，核心区别在 `eval_type`。
- `use_agent_server` 决定是否把模型推理拆成独立 HTTP 服务；True 不支持分布式。
- `vln_default_config.py` 只支持 H1，负责自动填充复杂默认配置。
- Ray 模式把 InternUtopia 环境分布到多机，普通模式用 torchrun 分布到多卡。
