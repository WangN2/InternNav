## 讲解

### 6.1 基线训练

基线模型（Seq2Seq / CMA / RDP）统一通过 `scripts/train/base_train/train.py` 启动：

```bash
python scripts/train/base_train/train.py --name <exp> --model-name <model>
```

NavDP 需要多 GPU：

```bash
torchrun --nproc_per_node=8 scripts/train/base_train/train.py --name <exp> --model-name navdp
```

### 6.2 InternVLA-N1 训练

**System 2：**

```bash
bash scripts/train/qwenvl_train/train_system2.sh
```

- 8 节点 × 8 GPU
- ZeRO-2
- LR 2e-5，vision tower 5e-6

**Dual System：**

```bash
bash scripts/train/qwenvl_train/train_dual_system.sh
```

- 从 System 2 checkpoint 开始
- 冻结 VLM，训练 System 1
- LR 1e-4

### 6.3 分布式评测

多 GPU 评测使用 `torchrun`：

```bash
bash scripts/eval/bash/torchrun_eval.sh scripts/eval/configs/h1_rdp_cfg.py
```

### 6.4 真实世界部署

**Server：**

```bash
python scripts/realworld/http_internvla_server.py --model_path checkpoints/InternVLA-N1-DualVLN
```

接收 `POST /eval_dual`：
- `image`: JPEG RGB
- `depth`: PNG depth（uint16，缩放 10000）
- `json`: `{"reset": bool, "idx": int}`

**Client：**

```bash
python scripts/realworld/http_internvla_client.py
```

ROS2 节点订阅 RGB-D 和里程计，发布 `Twist` 到 `/cmd_vel_bridge`。

### 6.5 常见工程坑点

| 坑点 | 说明 | 解决 |
|------|------|------|
| 子模块 | LongCLIP 和 diffusion-policy 是 submodule | `git submodule update --init --recursive` |
| DP 路径 | 部分脚本引用 `./src/diffusion-policy` | 实际在 `third_party/diffusion-policy` |
| pickle 安全 | AgentServer 用 pickle 传输观测 | 不要暴露到公网 |
| 真实服务安全 | Flask server 绑定 0.0.0.0:5801，无认证 | 公网部署需加认证/TLS |
| 数据格式 | v0.5 使用 `task` 字段 | 不再兼容 v0.1 |
| 数据/模型 | 数据和 checkpoint 不在仓库 | 需按 CI 路径或自行准备 |

## 关键代码走读

### `scripts/train/base_train/train.py:92-148`

NavDP 的自定义分布式初始化逻辑。

### `scripts/train/qwenvl_train/train_dual_system.sh`

两阶段训练中 System 1 的启动参数。

### `scripts/realworld/http_internvla_server.py`

Flask 端点、`InternVLAN1AsyncAgent` 加载、multipart 解析。

### `scripts/realworld/http_internvla_client.py`

ROS2 订阅、时间同步、轨迹坐标转换、MPC/PID 控制器选择。

## 小结

- 基线训练统一入口，NavDP 和 InternVLA-N1 需要多 GPU / DeepSpeed。
- 真实部署是 HTTP server + ROS2 client 架构，需注意坐标系转换与控制频率。
- 工程实践中要留意子模块、路径、安全、数据格式四个高频坑点。
